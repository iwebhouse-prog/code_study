# TASK-047. 프로젝트 생성 API

## 상태
완료

## 날짜
2026-11-10

## 작업 요약
새 공책을 만들어 주는 창구(`POST /api/v1/projects`)를 만들었습니다. 제목은 꼭 있어야 하고 설명은 적어도 되고 안 적어도 됩니다.

- 성공하면 **201**과 함께 새 프로젝트 정보를 돌려줍니다.
- 제목 앞뒤 공백은 지워집니다. "  My Todo  "는 "My Todo"로 저장됩니다.
- 제목이 비었거나(공백만 있어도) 255자를 넘으면 400으로 거절하고, 어느 칸이 문제인지(`title`)와 한국어 안내문을 함께 줍니다.
- 주인은 **로그인한 사람으로 정해집니다.** 요청에 `user_id`를 끼워 넣어도 무시합니다.

## 왜 이렇게 만들었나
- **주인을 요청서에서 받지 않습니다.** 도서관 대출증에 이름을 직접 쓰게 하면 남의 이름을 쓸 수 있으니, 직원이 회원증을 보고 채우는 것과 같습니다. 그래서 시험에서 남의 번호를 몰래 보내도 내 것으로 저장되는지 확인했습니다.
- **제목 규칙은 한 곳에만 둡니다.** 길이 검사는 이미 ProjectService에 있어서 이번 주소에서 다시 쓰지 않았습니다. 같은 규칙을 두 곳에 쓰면 한쪽만 고치는 사고가 나기 때문입니다.

## 기술 결정
제목 칸 필수 여부는 요청 양식(`ProjectCreate`)이, 내용 규칙(공백, 길이)은 서비스가 맡도록 나눴습니다. 계약서의 안내문("프로젝트 제목은 최소 1자 이상이어야 합니다.")이 서비스의 문장과 같아야 하기 때문입니다.

## 관련 개념
- **201 Created**: 200(성공)과 달리 "새로 만들었다"는 뜻의 성공 번호입니다.
- **서버가 정하는 값**: 주인, 번호, 시각처럼 사용자가 정하면 안 되는 값은 서버가 직접 채웁니다.

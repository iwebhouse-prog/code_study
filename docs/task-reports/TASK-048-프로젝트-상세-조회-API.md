# TASK-048. 프로젝트 상세 조회 API

## 상태
완료

## 날짜
2026-11-10

## 작업 요약
공책 하나를 펼쳐 보는 창구(`GET /api/v1/projects/{project_id}`)를 만들었습니다. 사물함 번호로 사물함을 여는 것과 같아서 **열쇠 주인인지 먼저 확인**합니다.

| 상황 | 응답 |
|---|---|
| 내 프로젝트 | 200과 프로젝트 정보 |
| 남의 프로젝트 | 403 "이 프로젝트에 접근할 권한이 없습니다." |
| 없는 번호, 휴지통에 있는 것 | 404 |
| 번호가 UUID 모양이 아님 | 400, 문제 칸 이름은 `project_id` |
| 로그인 안 함 | 401 |

## 왜 이렇게 만들었나
- **반드시 `get_for_user`만 씁니다.** T045 보고서에서 "주인 확인이 없는 `get`을 API에서 쓰지 말라"고 남긴 경고를 지켰습니다. 시험에서 남의 프로젝트가 정말 403으로 막히는지 확인합니다.
- 주소의 번호는 FastAPI가 UUID로 바꿔 줍니다. 글자가 이상하면 서비스까지 가지 않고 입구에서 400으로 돌려보냅니다. 우편물 주소가 이상하면 배달원이 출발하기 전에 반송하는 것과 같습니다.

## 기술 결정
`project_id`의 자료형을 UUID로 적어 두는 것만으로 400 처리가 되게 했습니다. 기존 오류 처리기가 "path, project_id"에서 `project_id`만 뽑아 주기 때문에 별도 코드가 필요 없었습니다.

## 관련 개념
- **UUID**: 추측하기 어려운 긴 무작위 번호입니다. 1, 2, 3 같은 순번이 아니라서 남의 번호를 짐작해 열어 보기 어렵습니다.
- **403과 404**: 403은 "있지만 당신 것이 아님", 404는 "없음"입니다.

## 주의할 점 (비고)
- 남의 프로젝트가 존재한다는 사실이 403으로 드러납니다. 계약서와 명세가 이 방식을 정했고, 번호가 무작위라 위험이 작다고 T045에서 판단했습니다.

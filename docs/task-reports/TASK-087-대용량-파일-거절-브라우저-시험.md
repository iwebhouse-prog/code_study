# TASK-087. 대용량(11MB) 파일 거절 브라우저 시험

## 상태
완료 (통과)

## 날짜
2026-11-16

## 작업 요약
10MB 제한(FR-014)을 넘는 **11MB 파일이 거절되고 한국어 안내가 나오는지** 확인했습니다. 막는 곳이 두 군데(브라우저, 서버)라서 둘 다 시험했습니다. 공항에서 체크인 카운터가 먼저 무게를 재고, 보안 검색대가 다시 재는 것과 같습니다.

**1. 화면(브라우저)에서**

| 단계 | 기대 | 결과 |
|---|---|---|
| 파일 업로드 탭 → `big.txt`(11,534,336바이트) 선택 → 태스크 만들기 | 서버로 보내기 전에 막힘 | 통과 — "파일 크기가 10MB를 초과합니다." 표시 |
| 네트워크 기록 | 새 `POST` 없음 | 통과 — 11MB를 서버로 보내지 않음 |

**2. 서버에서 (화면 검사를 우회해 직접 전송)**

브라우저 검사는 조작될 수 있으므로, 로그인된 브라우저에서 같은 11MB 파일을 API로 직접 보냈습니다.

| 항목 | 결과 |
|---|---|
| 상태 코드 | 413 |
| error | `file_too_large` |
| message | 파일 크기가 10MB를 초과합니다. |
| details | `max_size_mb: 10`, `uploaded_size_mb: 11` |
| suggestion | 더 작은 파일을 선택하거나 코드를 여러 태스크로 나누어 업로드하세요. |

거절 뒤 DB에 태스크 행이 생기지 않았고, 디스크에도 파일이 남지 않았습니다(태스크 폴더 3개 그대로).

## 기술 결정
- 서버 응답은 CHK084 예시와 같은 형식입니다. 화면 검사는 빠른 안내용, 서버 검사가 최종 판단이라는 계약서 원칙이 실제로 지켜졌습니다.

## 관련 개념
- **이중 검사**: 브라우저 검사는 사용자 편의, 서버 검사는 보안. 브라우저 검사만 믿으면 우회할 수 있습니다.

## 주의할 점 (비고)
- 브라우저에서 막을 때는 서버의 `suggestion`(해결 방법) 문장이 나오지 않습니다. 화면에도 같은 안내를 넣을지 정할 수 있습니다.
- 서버는 10MB 검사 전에 요청 전체를 메모리에 읽습니다. 운영 환경에서는 프록시(nginx 등)에도 크기 제한을 두는 것이 좋습니다(백엔드 보고).
- 직접 전송 시험의 콘솔 오류 2건(413, 400)은 의도한 거절입니다.

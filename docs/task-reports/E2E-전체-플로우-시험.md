# E2E 전체 플로우 시험 (2026-11-18)

## 요약
회원가입부터 AI 학습 문서 생성까지 **지금까지 만든 기능 전체**를 실제 브라우저(Playwright MCP, Chromium)로 한 사람의 사용자처럼 이어서 시험했습니다. 백엔드, Vite, PostgreSQL, Redis에 더해 **Celery 작업자와 실제 Gemini를 처음으로 함께** 돌렸습니다.

- 시나리오 8개 중 **7개 통과, 1개(S7) 부분 실패**.
- 버그·개선점 **4건 발견** (그중 #2가 심각).
- Gemini 실제 호출: 문서 생성 4건 성공(14~21초), 실패 시험 1건(잘못된 키, 요금 없음).
- 코드는 고치지 않았습니다(계획대로 발견만 기록).

## 발견한 문제
| # | 심각도 | 증상 | 재현 | 추정 원인 |
|---|---|---|---|---|
| 1 | 낮음 | 문서가 열려 있는 화면에 도착하면 장 메뉴가 1장이 아닌 **"4. 한 줄씩 살펴보기"를 현재 장**으로 표시 (직접 열면 1장) | 생성 중 화면에서 완료까지 기다림 (S6, S8 두 번 재현) | 문서가 나타날 때 코드 패널의 첫 스크롤 이벤트가 4장 항목을 선택 |
| 2 | **높음** | **Monaco 편집기 높이가 끝없이 커짐** (48줄 코드에 19만 px, 초당 약 1,690px 증가). 설명 패널도 7만 px로 늘어나 **장 메뉴를 눌러도 4장·7장 내용이 화면에 오지 않음**(T111), 코드 패널 스크롤 자체가 없어 **스크롤 연동 불가**(T112) | 큰 화면(lg 이상)에서 아무 문서나 열기 | `DocumentViewer`의 그리드는 `lg:h-[75vh]`이지만 `CodePanel`의 `<section className="space-y-2">`와 설명 패널 부모에 높이가 없어 `h-full`이 기준을 잃고, Monaco(`height="100%"`, `automaticLayout`)가 자기 크기를 따라 계속 자람 |
| 3 | 중간 | 코드 패널 위에서 마우스 휠을 굴려도 **페이지가 스크롤되지 않음** | 문서 화면에서 코드 위로 휠 | Monaco가 휠을 가져감 (#2가 고쳐지면 내부 스크롤로 해결될 가능성) |
| 4 | 중간 | 서버의 **API 키 오류**인데 사용자에게 "**이 코드로는** 학습 문서를 만들 수 없습니다. **코드를 확인한 뒤** 다시 업로드하세요."가 나옴 | 잘못된 키로 작업자 실행 | `ai_rejected`가 "키·설정 문제(운영자 탓)"와 "안전 필터 차단(내용 탓)"을 한데 묶음 |

## 잘 동작한 점
- 업로드→예약→작업자→Gemini→검증→저장→화면 갱신이 **처음 연결한 실제 환경에서 한 번에** 동작.
- 실패 시 재시도하지 않아야 할 오류(잘못된 키)를 0.9초 만에 끝내고, 다시 만들기로 회복.
- 콘솔 오류 13건은 모두 의도한 응답(로그인 확인 401, 시험한 403/404/400). 예상 밖 스크립트 오류 0건.

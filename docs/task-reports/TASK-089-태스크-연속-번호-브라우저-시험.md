## 상태

## 날짜

## 작업 요약
한 프로젝트에 **태스크 3개를 차례로 만들면 번호가 1, 2, 3으로 붙는지(FR-002, FR-003)** 확인했습니다. 은행 번호표처럼 순서대로 뽑히고, 실패한 시도는 번호를 쓰지 않아야 합니다.

T084~T086에서 같은 프로젝트("PW 태스크 업로드 시험")에 업로드 방식을 모두 바꿔 가며 차례로 만든 3개를 그대로 확인 대상으로 썼습니다.

| 순서 | 업로드 방식 | 제목 | 받은 번호 | 언어 |
|---|---|---|---|---|
| 1 | 파일 | 인사 함수 만들기 | **Task 1** | Python |
| 2 | 폴더 | React 폴더 구조 익히기 | **Task 2** | JavaScript |
| 3 | 붙여넣기 | 붙여넣기 합계 함수 | **Task 3** | Python |

확인한 곳:
- **업로드 완료 창**: 각각 "Task 1. …", "Task 2. …", "Task 3. …".
- **프로젝트 화면 목록**: 위에서부터 Task 1 → 2 → 3 순서(번호순 정렬).
- **DB**: `task_number` 1, 2, 3, 같은 프로젝트에 행 3개.

실패한 시도의 영향: T087·T088의 거절된 업로드(화면 2번, 직접 전송 2번)는 **태스크 행을 만들지 않았습니다**. 번호를 미리 써 버리지 않으므로 다음 태스크는 4번이 됩니다.

- 동시에 여러 요청이 와도 번호가 겹치지 않는지는 브라우저로 재현하기 어려워, 백엔드 통합 시험(동시 생성 5건 → 서로 다른 번호, T068)에 맡겼습니다.

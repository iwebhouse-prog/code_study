## 작업 요약
Gemini에게 7장 문서를 받아 **검사하고, 문제가 있으면 다시 요청하는 서비스**를 만들었습니다. 원고를 받아 검수하는 편집자에 비유하면, 우체국 사정으로 원고가 안 오면(일시 오류) 잠시 기다렸다 다시 부르고, 원고에 빠진 곳이 있으면(내용 오류) 고칠 점을 적어 돌려보냅니다.

**1. 검사기** `document_validator.py` — 문제 목록을 한국어 한 줄씩 돌려줍니다(빈 목록이면 저장 가능).
- 모양: T092의 스키마(`DOCUMENT_SCHEMA`)를 따라가며 형식, 필수·모르는 항목, 빈 글, 목록 개수(개념 카드 1~5, 실수 3~5), 고정 제목, `[TODO]` 같은 남은 자리표시(FR-095)를 봅니다. `notes`만 빈 글을 허용합니다.
- 코드 참조: 3·4장의 파일 경로가 실제로 올린 파일인지, 4장 줄 번호가 그 파일에 있는 줄인지 확인합니다.

**2. 생성 서비스** `document_generation_service.py` — `generate(files, language, complexity)`

| 실패 | 처리 |
|---|---|
| 일시 오류(시간 초과, 429, 5xx, 깨진 JSON) | 2초 → 4초 → 8초 기다리며 최대 3회 재시도 (research.md) |
| 소용없는 오류(잘못된 키, 안전 차단) | 즉시 실패 `ai_rejected` |
| 검사 실패 | 문제 목록을 붙인 프롬프트로 최대 2회 재요청 (FR-096) |
| 재시도를 다 씀 | `ai_unavailable` / `invalid_content` 실패 |

두 재시도 횟수는 따로 셉니다. 실패는 `DocumentGenerationError(reason, attempts, problems)`로 알려 줍니다.

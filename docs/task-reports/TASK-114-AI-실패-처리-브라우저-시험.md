## 작업 요약
AI 서비스가 실패할 때 **실패 안내와 다시 시도**가 동작하는지 확인했습니다. `.env`는 건드리지 않고, Celery 작업자 한 프로세스만 잘못된 API 키로 띄워 실패를 만들었습니다.

| 단계 | 결과 |
|---|---|
| 잘못된 키 작업자 + 새 태스크 | Gemini 400 → `AIRequestError` → **재시도 없이** `ai_rejected` (0.9초), DB `failed` |
| 화면 | 경고 + "다시 만들기" 버튼 |
| 정상 키 작업자로 교체 후 "다시 만들기" | `POST …/regenerate` 202 → 생성 중 화면 → 3초 간격 상태 확인 6번 → 18초 뒤 문서 표시 |

Playwright MCP(Chromium), 백엔드·Vite·PostgreSQL·Redis·Celery 작업자(`--pool=solo`)·실제 Gemini를 모두 띄운 상태에서 E2E 전체 플로우 시험의 일부로 진행했습니다. 전체 결과는 `E2E-전체-플로우-시험.md`에 있습니다.

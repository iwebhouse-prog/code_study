## 작업 요약
공책 표지를 고치는 창구(`PATCH /api/v1/projects/{project_id}`)를 만들었습니다. 이 작업의 핵심은 **"말하지 않은 칸"과 "비우라고 말한 칸"을 구별**하는 것입니다.

- 보내지 않은 칸은 그대로 둡니다.
- `"description": null` 이나 `""` 를 보내면 설명을 지웁니다.
- `"title": null` 은 거절합니다. 제목은 지울 수 없습니다.
- 빈 요청 `{}` 은 아무것도 바꾸지 않고 200을 돌려줍니다.
- 남의 프로젝트는 403이며 내용이 바뀌지 않습니다. 없으면 404, 번호가 이상하면 `project_id` 칸 400입니다.

## 왜 이렇게 만들었나
- 음식 주문에 비유하면 "양파 빼 주세요"(비우기)와 아무 말도 안 하는 것(그대로 두기)은 다릅니다. 요청서에서 **실제로 적힌 칸만 골라내는 함수**(`changes`)를 만들어 서비스의 `UNSET`(안 건드림 표시)과 이어 주었습니다.
- 나쁜 제목은 아무것도 바뀌기 전에 거절됩니다. 시험에서 거절 뒤에도 옛 제목이 그대로인지 DB에서 직접 읽어 확인했습니다.
- 주인 확인은 `update_for_user`가 합니다. 이번 주소에는 확인 코드를 다시 쓰지 않았습니다.

## 기술 결정
요청 양식은 `title: str | None = None`으로 두고, 값이 실제로 null일 때만 오류를 내는 검사기를 달았습니다. 이 검사기는 값이 아예 없을 때는 실행되지 않으므로 "안 보냄"과 "null 보냄"이 자연스럽게 갈립니다.

## 관련 개념
- **PATCH와 PUT**: PUT은 서류 전체를 새로 쓰는 것이고 PATCH는 고칠 칸만 보내는 것입니다.
- **센티널 값(UNSET)**: "아직 정해지지 않음"을 None과 따로 표시하는 특별한 표식입니다.

# TASK-041. 보호 페이지 접근 브라우저 테스트

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
로그인하지 않은 사람이 회원 전용 화면의 주소를 직접 쳐서 들어오려 할 때, 막히고 로그인 화면으로 안내되는지 실제 브라우저에서 확인했습니다. 회원증 없이 열람실 문을 열려는 사람을 안내 데스크로 돌려보내는지 본 것입니다.

진행 순서와 결과는 다음과 같습니다.

1. 로그아웃해 비로그인 상태를 만들었습니다.
2. 주소창에 회원 전용 화면인 `/trash`(휴지통)를 직접 입력했습니다.
3. 화면은 서버에 "지금 누구인지" 물었고, 서버는 **401(로그인 안 됨)** 으로 답했습니다.
4. 화면은 휴지통을 보여 주지 않고 **로그인 화면(`/login`)으로 이동**했습니다.
5. 그 자리에서 로그인하자 처음 가려던 `/trash`로 돌아갔습니다. 문지기가 "어디 가려던 길이었는지"를 기억해 둔 것입니다(T040에서 함께 확인).

확인 중에 서버에 묻는 동안 아주 잠깐 "확인 중" 상태가 있었습니다. 이 순간에는 화면을 바로 내쫓지 않고 기다리도록 만든 것(T037)이 의도대로 동작했습니다. 로그인한 사람이 새로고침할 때 로그인 화면으로 잘못 튕겨 나가는 일이 없었습니다.

## 왜 이렇게 시험했나
- 사람들은 즐겨찾기나 붙여 넣은 주소로 화면 중간에 바로 들어옵니다. 그래서 메뉴를 누르는 길이 아니라 주소를 직접 입력하는 길을 시험했습니다.
- "막는 것"과 "로그인 후 원래 자리로 돌려보내는 것"을 함께 보아야 사용자가 불편하지 않습니다.

- 같은 동작은 자동 테스트(T037 ProtectedRoute 시험)로도 검증되어 있습니다.

## 기술 결정
- 화면에서 막는 것은 편의를 위한 것입니다. 진짜 보호는 서버가 합니다. 서버의 모든 회원 전용 주소는 쿠키 없이 부르면 401로 거절합니다(T027).

## 관련 개념
- **화면 보호와 서버 보호**: 화면의 문지기는 사용자를 안내할 뿐이고, 데이터는 서버의 문지기가 지킵니다. 둘 다 있어야 안전하고 편리합니다.
- **세 가지 상태**: "확인 전", "로그인함", "로그인 안 함"을 따로 둡니다. "확인 전"을 "로그인 안 함"으로 취급하면 새로고침할 때마다 로그인 화면이 잠깐 깜빡입니다.

## 주의할 점 (비고)
- 로그인 후 돌아갈 주소로는 우리 사이트 안의 주소만 받습니다. 바깥 사이트 주소는 무시합니다(T036, 엉뚱한 사이트로 끌려가는 것을 막기 위함).

# TASK-030. 로그아웃 API (POST /auth/logout)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
손님이 나갈 때 **입장권을 회수하고 쿠키를 지우는 출구**를 만들었습니다. 이 출구는 어떤 경우에도 204(성공, 내용 없음)로 답합니다. 로그인 상태가 아니어도, 쿠키가 엉터리여도, 이미 로그아웃한 뒤여도 마찬가지입니다.

하는 일은 두 가지입니다.
1. 쿠키에 긴 입장권(`refresh_token`)이 있으면 서버 장부에서 무효로 바꿉니다.
2. 두 쿠키를 같은 이름·같은 경로로 Max-Age=0을 달아 돌려보내 브라우저가 지우게 합니다.

호텔 퇴실 절차와 비슷합니다. 카드키를 프런트에 반납하면 그 카드키는 바로 무효가 되고, 이미 반납했거나 잃어버린 손님도 "퇴실 처리되었습니다"라는 같은 답을 받습니다. 그래서 프론트엔드는 이 주소가 실패할까 봐 따로 걱정할 필요가 없고, 화면에서는 응답과 상관없이 로그인 화면으로 이동하면 됩니다.

## 왜 이렇게 만들었나
- **언제나 성공합니다.** 놀이공원 출구에서 표가 없다고 막으면 사람이 갇힙니다. 나가려는 사람은 그냥 나가게 하는 편이 안전합니다. 화면도 로그아웃 실패를 처리할 필요가 없습니다.
- **이 기기 한 장만 회수합니다.** 다른 기기의 로그인은 그대로 유지됩니다. 전체 로그아웃은 별도 기능입니다.
- **지우는 쿠키도 옵션을 맞춥니다.** 쿠키는 이름과 경로가 같아야 지워집니다. 그래서 심을 때 쓴 경로(`/`, `/api/v1/auth`)를 같은 도우미에서 그대로 씁니다.
- **회수는 서비스에 맡깁니다.** 장부 수정은 `UserService.logout()`이 하고, 주소 처리 코드는 쿠키만 다룹니다.

## 관련 개념
- **세션 무효화**: 서버가 장부에서 토큰을 "사용 불가"로 표시해, 훔친 토큰이 있어도 못 쓰게 하는 일입니다.
- **204 No Content**: 성공했지만 돌려줄 내용이 없다는 뜻입니다.

## 주의할 점 (비고)
- 짧은 입장권은 서버에서 취소할 수 없어 최대 15분 남지만, 쿠키가 지워지므로 이 브라우저에서는 쓸 수 없습니다.
- 로그아웃 요청은 `/api/v1/auth` 아래 주소라서 긴 입장권 쿠키가 자동으로 함께 갑니다. 주소를 다른 곳으로 옮기면 쿠키가 따라가지 못해 회수가 되지 않으니 주의하세요.
- 장부에 없는 엉터리 토큰이 와도 오류를 내지 않고 조용히 넘어갑니다. 같은 요청을 여러 번 보내도 결과가 같습니다.
- 프론트엔드는 로그아웃 후 캐시를 비우고 로그인 화면으로 이동해야 합니다(계약서 규칙).

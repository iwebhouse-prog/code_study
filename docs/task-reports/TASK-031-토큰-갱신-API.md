# TASK-031. 토큰 갱신 API (POST /auth/refresh)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
짧은 입장권(15분)이 끝났을 때 긴 입장권(7일)을 보여 주고 **새 입장권 두 장으로 바꿔 주는 교환 창구**를 열었습니다. 쿠키의 `refresh_token`을 읽어 `TokenService.rotate()`로 교체하고, 새 쿠키 두 개와 회원 정보를 200으로 돌려줍니다.

실패하면 어떤 이유든(쿠키 없음, 만료, 무효화, 재사용) 401 `session_expired`이며, **이때 쿠키 두 개도 함께 지웁니다.** 화면은 이 답을 받으면 로그인 화면으로 갑니다.

회원 전용 사무실 출입증을 예로 들면, 하루짜리 임시 출입증이 끝났을 때 7일짜리 사원증을 내고 새 임시 출입증과 새 사원증을 받는 절차입니다. 이때 받은 사원증은 즉시 폐기되고, 새것만 유효합니다. 누군가 옛 사원증을 복사해 다시 내밀면 경비실이 "복제 의심"으로 보고 해당 직원의 모든 출입증을 한꺼번에 무효로 만듭니다.

## 왜 이렇게 만들었나
- **입장권은 한 번만 씁니다.** 교환한 낡은 입장권을 다시 내밀면 도난으로 보고 그 회원의 모든 로그인을 끝냅니다(T026 규칙). 복사한 열쇠가 쓰였을 가능성이 있으면 자물쇠를 통째로 바꾸는 것과 같습니다.
- **실패 답에 직접 쿠키 삭제를 붙입니다.** 오류를 던지면 응답이 새로 만들어져 쿠키 삭제 지시가 사라집니다. 그래서 오류 본문을 직접 만들어 쿠키를 지운 뒤 돌려줍니다. 쓸모없어진 쿠키가 브라우저에 남지 않습니다.
- **회원 정보는 새 짧은 입장권에서 찾습니다.** 교환 서비스는 입장권 쌍만 돌려주므로, 새 입장권의 주인을 확인해 회원을 조회합니다. 서비스를 바꾸지 않으려는 선택입니다.

## 기술 결정
- 회원이 사라진 경우는 DB 구조상 거의 불가능하지만, 안전하게 `session_expired`로 답하고 가짜 서비스로 시험했습니다.
- `pyproject.toml`에 커버리지 설정(`greenlet`, `thread`)을 넣어 await 이후 줄이 누락으로 잡히던 문제를 풀었습니다.

## 관련 개념
- **토큰 회전**: 쓸 때마다 새것으로 바꾸고 낡은 것은 폐기하는 방식입니다.
- **단일 비행**: 프론트엔드가 갱신 요청을 한 번에 하나만 보내는 규칙입니다. 동시에 둘이 가면 두 번째가 재사용으로 오해받습니다.

## 주의할 점 (비고)
- 프론트엔드는 반드시 갱신을 한 번에 하나만 보내야 합니다.
- 두 탭이 거의 동시에 갱신하면 두 번째 요청이 "재사용"으로 판정되어 모든 로그인이 끝날 수 있습니다. 탭 사이 조율은 프론트엔드 몫입니다.
- 갱신 성공 응답에도 회원 정보가 들어 있으므로, 별도로 `/auth/me`를 다시 부르지 않아도 됩니다.
- 이 주소는 `/api/v1/auth` 아래에 있어야만 긴 입장권 쿠키를 받습니다. 그래서 경로 상수 `AUTH_COOKIE_PATH`가 라우터 접두사와 같다는 점을 단위 시험으로 지킵니다.

# TASK-029A. 내 정보 조회 API (GET /auth/me)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
화면이 처음 열릴 때 "지금 로그인한 사람이 누구죠?" 하고 묻는 **안내 데스크**를 만들었습니다. 쿠키의 입장권이 유효하면 회원 정보를 돌려주고, 아니면 이유에 따라 401을 돌려줍니다. T027에서 만든 문지기(`CurrentUser`)를 처음 실제 주소에 단 작업입니다.

답은 세 가지로 나뉩니다.
- 입장권이 없음: `unauthorized` (로그인이 필요합니다)
- 기간 만료: `token_expired` (화면이 조용히 새 입장권을 받고 다시 시도)
- 가짜이거나 탈퇴한 회원: `session_expired` (다시 로그인)

이 주소는 프론트엔드가 가장 먼저 부르는 주소이기도 합니다. 화면이 새로 열리면 인증 상태가 "아직 모름"인데, 이 주소의 답으로 "로그인됨"인지 "손님"인지 정해집니다. 건물에 들어서자마자 경비원이 "출입증 확인해 드릴게요" 하고 한 번 스캔하는 것과 같습니다. 그래서 답이 빠르고 단순해야 합니다.

## 왜 이렇게 만들었나
- **주소 처리 코드는 한 줄입니다.** 문지기가 이미 확인과 회원 조회를 끝내므로, 이 주소는 받은 회원을 응답 형식으로 바꿔 돌려주기만 합니다. 로비 안내 직원이 손님 명찰을 이미 확인한 상태에서 이름표만 읽어 주는 것과 같습니다.
- **응답 형식을 따로 정의했습니다.** `UserResponse`에는 계약서의 다섯 항목만 있습니다. 회원 객체를 그대로 내보내면 나중에 칸이 추가될 때 비밀번호 암호문이 새어 나갈 수 있어서, 보여 줄 것만 적어 둔 틀을 쓰는 것입니다.
- **가입·로그인·갱신과 같은 틀을 씁니다.** 프론트엔드가 한 가지 모양만 다루면 되도록 했습니다.

## 관련 개념
- **응답 모델**: 밖으로 내보낼 항목을 미리 적어 둔 틀입니다. 적히지 않은 항목은 자동으로 빠집니다.
- **멱등 조회**: 몇 번을 불러도 데이터가 바뀌지 않는 요청입니다.

## 주의할 점 (비고)
- 프론트엔드는 `skill_level`을 `skillLevel`로 바꿔 씁니다. `last_login_at`은 가입 직후에는 `null`입니다.
- 요청마다 회원 대장을 한 번 조회합니다.
- 입장권을 `Authorization` 헤더로 보내는 방식은 열려 있지 않습니다. 쿠키만 받습니다(T027과 동일).
- 응답에 칸을 추가하려면 `UserResponse`와 계약서, 프론트엔드의 `AuthUser` 변환을 함께 고쳐야 합니다. 세 곳이 같은 약속을 공유하기 때문입니다.
- 시각 값은 `2026-11-09T01:00:00+00:00`처럼 시간대가 붙은 형식으로 나갑니다.

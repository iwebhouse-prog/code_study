# TASK-052. 프로젝트 생성 모달

## 상태
완료

## 날짜

## 작업 요약
"새 프로젝트" 버튼을 누르면 화면 위에 떠오르는 **입력 창(대화상자)** 을 만들었습니다. 관공서 민원 창구에서 신청서를 받는 것과 같습니다. 제목은 꼭 적어야 하고 설명은 비워도 되며, 창구 직원(서버)이 돌려보내면 그 이유를 신청서 옆에 바로 적어 줍니다.

## 왜 이렇게 만들었나
- **제출 전에 먼저 확인합니다.** 앞뒤 공백을 뺀 제목이 1자 이상 255자 이하여야 합니다. 서버와 똑같은 규칙이라, 빈 제목을 서버까지 보내 거절당하는 헛걸음을 줄입니다. 그래도 서버의 답이 최종이라 서버가 거절하면 그대로 보여 줍니다.
- **오류 위치를 구분합니다.** 제목 문제는 제목 칸 바로 아래에 붉은 글씨로(화면 읽기 도구도 읽도록 연결), 그 밖의 서버 메시지는 창 위쪽 경고 상자에 보여 줍니다.
- **저장 중에는 버튼을 잠급니다.** "만드는 중…"으로 바뀌고 눌러지지 않아, 같은 프로젝트가 두 번 만들어지지 않습니다.
- **저장 방법은 밖에서 받습니다.** 창은 `onSubmit` 함수를 받아 실행만 합니다. 성공 뒤 안내와 화면 이동은 대시보드가 맡습니다.

## 기술 결정
- Radix 대화상자를 썼습니다. 키보드 이동(Tab 가두기, Esc로 닫기)과 접근성을 직접 짜지 않아도 됩니다.
- 브라우저 기본 검사(`required` 경고 말풍선)는 꺼 두고(`noValidate`) 우리 문구로 통일했습니다. 제목 칸에는 `required` 표시만 남겼습니다.
- 글자 수 제한은 입력칸에서 막지 않고 제출 때 알려 줍니다. 붙여넣기한 긴 글이 조용히 잘리는 것보다 이유를 알려 주는 편이 낫습니다.

## 관련 개념
- **모달(대화상자)**: 뒤 화면을 어둡게 하고 그 창에만 집중시키는 팝업입니다.
- **클라이언트 검증과 서버 검증**: 건물 입구의 안내 데스크(클라이언트)와 금고 앞 심사(서버)입니다. 안내 데스크는 빠르지만 최종 결정은 심사가 합니다.

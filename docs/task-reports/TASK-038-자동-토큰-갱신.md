# TASK-038. 자동 토큰 갱신 (useAuth)

## 상태
완료

## 날짜

## 작업 요약
로그인이 **조용히 유지되게** 하는 장치를 만들었습니다. 세 부분입니다.

1. **앱 시작 확인**: 앱을 열면 서버에 "내가 누구죠?"(`GET /auth/me`)를 물어 로그인 여부를 정합니다.
2. **자동 갱신**: 입장권(액세스 토큰)은 15분만 유효합니다. 서버가 "입장권 만료"(`token_expired`)라고 답하면 화면이 알아서 새 입장권을 받고, 하던 요청을 **한 번만** 다시 보냅니다. 사용자는 아무것도 못 느낍니다.
3. **세션 종료 정리**: 갱신도 안 되면(`session_expired`) 로그인 정보와 저장된 데이터를 모두 비우고, 문지기가 로그인 화면으로 안내합니다.

## 왜 이렇게 만들었나
- **갱신은 한 번에 하나만(single-flight)**이 가장 중요합니다. 화면이 요청 세 개를 동시에 보냈는데 모두 만료로 돌아왔다고 합시다. 각자 갱신하면, 첫 갱신으로 바뀐 재발급권을 나머지가 옛것으로 또 내밉니다. 서버는 이를 도난으로 보고 **모든 기기에서 로그아웃**시킵니다. 그래서 첫 요청이 갱신하는 동안 나머지는 같은 결과를 함께 기다립니다. 은행 창구에서 한 사람이 통장 재발급을 받는 동안 같은 통장으로 다른 직원이 또 재발급하지 못하게 막는 것과 같습니다.
- **재시도는 한 번뿐**: 다시 보낸 요청도 만료라면 무한 반복하지 않고 오류를 돌려줍니다.
- **갱신 요청 자신은 갱신하지 않습니다.** 그러지 않으면 자기 자신을 기다리는 교착 상태가 됩니다.

## 기술 결정
- 오류 객체에 원래 요청 정보를 추가해야 재전송할 수 있어서 `ApiError`에 `config`를 더했습니다. 기존 시험에는 영향이 없습니다.
- 서버에 연결하지 못하면 "로그인 안 함"으로 처리해 로그인 화면에서 다시 시도하게 합니다.
- 로그아웃은 서버가 응답하지 않아도 이 기기에서는 반드시 로그아웃 처리합니다.

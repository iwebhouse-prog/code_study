# TASK-032. 회원가입 폼 (RegisterForm)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
회원가입 화면에서 쓰는 **입력 양식**을 만들었습니다. 이메일 칸, 비밀번호 칸, "회원가입" 버튼이 있는 종이 신청서라고 생각하면 됩니다. 칸마다 이름표(라벨)가 붙어 있고, 잘못 적으면 그 칸 바로 아래에 빨간 글씨로 이유가 나옵니다. 서버가 보낸 전체 안내문은 맨 위 경고 상자에 나옵니다. 버튼을 누르면 "가입 중…"으로 바뀌고 잠겨서, 급한 마음에 두 번 눌러도 신청서가 두 장 접수되지 않습니다.

미리 확인하는 규칙은 서버와 똑같이 맞췄습니다. 비밀번호는 8자 이상이고 영문자와 숫자를 모두 넣어야 하며, 72바이트를 넘으면 안 됩니다. 한글은 한 글자가 3바이트라서 한글만 24자를 넘기면 걸립니다.

## 왜 이렇게 만들었나
- **창구 직원이 미리 훑어보는 것과 같습니다.** 접수 창구에서 "도장이 빠졌네요"라고 바로 알려 주면 서류를 서버까지 보냈다가 돌려받는 시간을 아낍니다. 그래도 **최종 판단은 서버**가 합니다. 서버가 다른 답을 주면 그 답을 그대로 보여 줍니다.
- **로그인 양식과 뼈대를 함께 씁니다.** 두 양식은 칸 두 개와 버튼 하나로 거의 같아서, 공통 부분(`CredentialsForm`)을 한 번만 만들고 가입용 규칙만 따로 끼웠습니다. 한쪽을 고치면 다른 쪽도 같이 좋아집니다.
- **화면 읽어 주는 프로그램을 배려했습니다.** 오류가 난 칸에는 "잘못됨" 표시와 오류 문장 연결을 달아 두었습니다.

## 기술 결정
- 브라우저 기본 검사 대신 `noValidate`를 쓰고 직접 한국어로 안내합니다. 브라우저마다 문구가 달라지기 때문입니다.
- 서버가 알려 주는 칸 오류(`fieldErrors`)는 `email`, `password` 두 칸에만 표시합니다.

## 관련 개념
- **클라이언트 검사와 서버 검사**: 앞쪽 검사는 친절함을, 뒤쪽 검사는 안전을 맡습니다. 사용자는 앞쪽을 우회할 수 있으니 뒤쪽이 꼭 있어야 합니다.
- **바이트**: 컴퓨터가 글자를 저장하는 크기 단위입니다. 영문은 1, 한글은 3입니다.

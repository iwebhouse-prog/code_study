# TASK-050. 프로젝트 삭제 API

## 상태
완료

## 날짜
2026-11-10

## 작업 요약
공책을 **쓰레기통이 아니라 휴지통에 넣는** 창구(`DELETE /api/v1/projects/{project_id}`)를 만들었습니다. 성공하면 내용이 없는 **204**로 답합니다.

- 프로젝트는 지워지지 않고 "휴지통" 상태가 되며 30일 뒤 삭제될 날짜가 기록됩니다(T043, T044).
- 그 뒤부터 목록과 상세 조회에서는 보이지 않습니다(404).
- 같은 프로젝트를 또 지우면 404입니다.
- 남의 프로젝트는 403이고 상태가 그대로 "활성"으로 남습니다. 없는 번호는 404, 이상한 번호는 `project_id` 칸 400입니다.

## 왜 이렇게 만들었나
- 실수로 지워도 30일 동안 되살릴 수 있게 하려는 명세(FR-009) 때문에 **진짜로 지우지 않고 표시만 바꿉니다.** 사무실 서류를 바로 파쇄하지 않고 보관함에 한 달 두는 것과 같습니다.
- 응답에 본문이 없는 204는 "처리했고 더 드릴 말은 없다"는 뜻이라 화면 쪽이 바로 알림을 띄우고 대시보드로 이동하면 됩니다.
- 반드시 `move_to_trash_for_user`를 써서 주인 확인이 먼저 일어납니다.

## 기술 결정
삭제 주소는 값을 돌려주지 않는 함수(`-> None`)로 만들고 상태 번호만 204로 지정했습니다. 별도 응답 객체를 만들지 않아 가장 단순합니다.

## 관련 개념
- **소프트 삭제**: 데이터를 지우지 않고 "삭제됨" 표시만 하는 방식입니다. 되살리기와 감사 기록에 유리합니다.
- **멱등성**: 같은 요청을 반복해도 결과가 변하지 않는 성질입니다. 여기서는 두 번째가 404이므로 상태는 같습니다.

## 주의할 점 (비고)
- 프로젝트 안의 태스크도 함께 휴지통에 넣는 일(FR-009D)은 태스크 모델이 생기는 T061에서 합니다. 되살리기와 30일 뒤 영구 삭제도 별도 작업입니다.

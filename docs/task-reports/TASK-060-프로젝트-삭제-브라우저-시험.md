## 상태
완료 (휴지통 화면 확인은 T183으로 이월)

## 날짜
2026-11-10

## 작업 요약
프로젝트를 삭제하면 **완전히 지워지지 않고 휴지통으로 옮겨지는지(소프트 삭제)** 실제 브라우저(Playwright MCP)와 DB로 확인했습니다. 컴퓨터의 "삭제"가 파일을 바로 없애지 않고 휴지통에 넣는 것과 같습니다.

### 시험 순서와 결과
| 단계 | 행동 | 기대 | 결과 |
|---|---|---|---|
| 1 | 상세 화면에서 "삭제" | 확인 창: "…휴지통으로 이동하며, 30일 안에는 복구할 수 있습니다." | 통과 (처음 초점은 "취소") |
| 2 | 확인 창의 "삭제" | 대시보드로 이동 | 통과 (`DELETE` 204) |
| 3 | 대시보드 확인 | 프로젝트가 사라지고 빈 상태 안내 | 통과 (`GET /projects` 200) |
| 4 | 지운 프로젝트 주소로 직접 접속 | "프로젝트를 열 수 없습니다" 안내 | 통과 (서버 404) |
| 5 | DB 조회 | 행은 남아 있고 `trashed` | 통과 |
| 6 | `/trash` 화면 | 지운 프로젝트 표시 | **확인 불가** (자리표시 화면) |

DB 조회 결과(5단계): `deletion_status = trashed`, `trashed_at = 2026-11-10 02:29:41 UTC`, `scheduled_deletion_at = 2026-12-10 02:29:41 UTC` → **정확히 30일 뒤 영구 삭제 예정**.

## 기술 결정
- **"휴지통에 보이는지"는 지금 화면으로 확인할 수 없습니다.** 휴지통 화면(T181)과 휴지통 서비스(T180)가 아직 없고, `/trash`는 제목만 있는 자리표시입니다. 이 부분은 이후 단계의 **T183**("삭제 → 휴지통에 30일 남은 기간과 함께 표시")이 같은 내용을 확인하므로 거기로 넘겼습니다. 대신 DB에서 휴지통 상태와 30일 일정을 직접 확인했습니다.
- 4단계의 콘솔 오류(404) 1건은 지운 프로젝트를 일부러 열었기 때문에 생긴 정상 응답입니다.

## 관련 개념
- **소프트 삭제**: 행을 지우지 않고 "삭제됨" 표시만 해 두는 방식입니다. 실수로 지워도 복구할 수 있습니다.

## 주의할 점 (비고)
- 삭제 알림(토스트)은 이번에는 화면 기록에 잡히지 않았습니다(3초 뒤 사라짐). 이전 Chrome 시험에서 표시를 확인한 바 있습니다.

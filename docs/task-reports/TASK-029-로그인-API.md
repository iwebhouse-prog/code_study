# TASK-029. 로그인 API (POST /auth/login)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
이미 가입한 손님이 이메일과 비밀번호를 보여 주면 **신분 확인 후 입장권 두 장을 쿠키로 건네는 창구**를 열었습니다. 맞으면 200과 회원 정보, 틀리면 401입니다. 입장권 쿠키의 모양(이름, 경로, 유효 시간, 보안 옵션)을 정하는 공용 도우미도 이 작업에서 만들었습니다.

쿠키 규칙은 계약서 그대로입니다.
- `access_token`: 15분(900초), 모든 경로에서 사용
- `refresh_token`: 7일(604800초), `/api/v1/auth` 아래에서만 전송
- 둘 다 HttpOnly, SameSite=Strict, 운영 환경에서만 Secure

비유하자면 놀이공원 입구에서 신분증을 보여 주고 손목밴드를 받는 일입니다. 밴드는 손목에 채워져 있어 손님이 직접 풀어 보거나 고칠 수 없고(HttpOnly), 공원 안 매표소에서만 확인됩니다. 로그인에 성공하면 마지막 로그인 시각도 함께 기록되어, 응답의 `last_login_at`에 값이 들어옵니다. 가입 직후에는 이 값이 비어 있습니다.

## 왜 이렇게 만들었나
- **틀린 이유를 알려 주지 않습니다.** 없는 이메일과 틀린 비밀번호가 똑같은 401 답을 받습니다. 은행 창구에서 "그 계좌는 없습니다"라고 말하면 남의 계좌 유무를 알려 주는 셈이라서 같은 말만 합니다.
- **긴 입장권은 좁은 길에서만 씁니다.** 7일짜리 입장권이 모든 요청에 따라가면 노출 기회가 늘어납니다. 그래서 인증 주소에만 보냅니다.
- **유효 시간은 설정에서 읽습니다.** 숫자를 코드에 박지 않고 `JWTConfig`의 값에서 계산하므로, 설정을 바꾸면 쿠키도 함께 바뀝니다.
- **운영 여부는 설정에서 판단합니다.** 개발 중인 `http://localhost`에서는 Secure 쿠키가 저장되지 않기 때문에, 운영에서만 켭니다.

## 기술 결정
- 로그인 본문의 비밀번호는 길이를 따로 제한하지 않았습니다. 틀리면 어차피 401입니다.
- 커버리지 도구가 비동기 코드 뒤쪽 줄을 놓쳐서 `pyproject.toml`에 `concurrency = greenlet, thread`를 추가했습니다. 검사 기준을 낮춘 것이 아니라 측정 방식을 바로잡은 것입니다.

## 관련 개념
- **SameSite=Strict**: 다른 사이트에서 출발한 요청에는 쿠키를 붙이지 않는 옵션입니다.
- **Max-Age**: 쿠키가 살아 있는 초 단위 시간입니다.

## 주의할 점 (비고)
- 로그인 시도 횟수 제한은 없습니다(후속 작업).
- 위조 요청 방어는 T199 범위입니다.
- 운영 환경에서는 HTTPS가 필수입니다. Secure 쿠키는 암호화된 연결에서만 전달되므로, 운영 서버를 HTTP로 열면 로그인해도 쿠키가 저장되지 않습니다.
- 같은 브라우저에서 다시 로그인하면 쿠키가 새것으로 덮어써지고, 이전 긴 입장권은 장부에 남지만 쿠키가 없어 쓰이지 않습니다. 만료된 장부 기록 정리는 후속 작업입니다.
- 비밀번호 확인에는 0.2초 안팎이 걸립니다. 서버가 멈추지 않도록 별도 작업 줄에서 처리됩니다(T025).

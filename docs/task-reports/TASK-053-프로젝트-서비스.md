## 작업 요약
화면이 서버의 프로젝트 기능을 부를 때 쓰는 **전화 교환대**를 만들었습니다. 화면은 "목록 줘", "만들어 줘", "하나 보여 줘", "고쳐 줘", "지워 줘" 다섯 가지만 말하면 되고, 어느 주소로 어떤 방식으로 걸지는 교환대가 압니다.

| 업무 | 서버에 하는 일 |
|---|---|
| list | GET /projects |
| get | GET /projects/{id} |
| create | POST /projects |
| update | PATCH /projects/{id} |
| remove | DELETE /projects/{id} |

## 왜 이렇게 만들었나
- **이름표를 바꿔 붙입니다.** 서버는 `created_at`처럼 밑줄 이름을 쓰고, 화면 코드는 `createdAt`처럼 씁니다. 번역은 이 파일 한 곳에서만 하므로 다른 파일은 서버 모양을 몰라도 됩니다. 기존 로그인 서비스와 같은 방식입니다.
- **고칠 때는 바뀐 것만 보냅니다.** 계약서 규칙입니다. 제목만 바뀌었으면 제목만 보냅니다. 설명을 지우려면 `null`을 보내야 하고, 이것은 "빈 칸 남기기"와 다릅니다. 보내지 않은 항목은 서버가 그대로 둡니다.
- 프로젝트 번호에 `/` 같은 글자가 있어도 주소가 깨지지 않도록 안전한 글자로 바꿔서(encode) 붙입니다.

## 기술 결정
- 서버 오류는 이미 공용 연결 객체가 `ApiError`로 바꿔 주므로 이 서비스에서는 따로 잡지 않고 그대로 위로 올립니다. 어떤 문구를 보여 줄지는 화면이 정합니다.
- "무엇이 바뀌었는지" 비교는 서비스가 아니라 화면이 합니다. 서비스는 받은 변경 내용을 그대로 전달만 합니다.

## 관련 개념
- **CRUD**: 만들기(Create), 읽기(Read), 고치기(Update), 지우기(Delete). 대부분 앱의 기본 네 가지 동작입니다.
- **PATCH와 PUT**: PUT은 서류 전체를 새로 제출하고, PATCH는 고친 줄만 적어 제출하는 방식입니다.

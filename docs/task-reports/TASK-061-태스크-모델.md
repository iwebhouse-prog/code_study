## 작업 요약
프로젝트 안의 학습 단위인 **태스크를 DB 표(`tasks`)와 연결하는 SQLAlchemy 모델**을 만들었습니다. 표 자체는 T009 마이그레이션에 이미 있었고, 이번에는 파이썬 코드가 그 표를 읽고 쓸 수 있게 "설계도"를 맞춘 것입니다. 책장(DB 표)은 이미 있고, 책마다 붙일 분류 라벨(모델)을 만든 셈입니다.

1. **칸 구성**: 프로젝트 id, 태스크 번호, 제목, 설명, 올린 방식(file/folder/paste), 만든·수정 시각, 휴지통 3칸. 마이그레이션과 칸·형식·빈칸 허용이 모두 같은지 실제 DB로 확인했습니다.
2. **규칙**: 제목 5자 이상(FR-008), 설명 500자 이하(FR-009), 올린 방식은 세 가지만, 한 프로젝트 안에서 번호 중복 금지.
3. **순번 도우미**: `Task.next_number_query(project_id)`는 "그 프로젝트의 가장 큰 번호 + 1"을 계산합니다. 태스크가 없으면 1입니다.
4. **번호 고정**: 한 번 받은 번호는 바꾸려 하면 `ValueError`가 납니다(FR-004, FR-005 재정렬 금지).
5. **관계**: `Project.tasks`는 항상 번호 순으로 나옵니다(FR-003). 프로젝트가 지워지면 태스크도 함께 지워집니다.

## 기술 결정
- **휴지통 태스크의 번호도 셉니다.** 2번을 휴지통에 넣고 새로 만들면 3번이 됩니다. 2번을 다시 쓰면 휴지통에서 복구할 때 번호가 겹치기 때문입니다.
- **번호 매기기는 모델이 아니라 서비스(T068)가 합니다.** 모델은 계산 쿼리만 줍니다. 두 요청이 동시에 같은 번호를 읽으면 DB의 중복 금지 규칙이 두 번째를 막고, 재시도나 잠금은 T068에서 정합니다.
- 제약 이름은 PostgreSQL이 붙인 이름(`tasks_upload_method_check` 등)에 맞췄습니다.

## 관련 개념

# TASK-057. 프로젝트 생성 브라우저 시험

## 상태
완료 (통과)

## 날짜
2026-11-10

## 작업 요약
실제 브라우저(Playwright MCP, Chromium)에서 **새 프로젝트를 만들고 대시보드에 나타나는지** 확인했습니다. 단위 시험은 서버를 흉내 낸 가짜 응답으로 돌지만, 이번 시험은 실제 백엔드(127.0.0.1:8000)와 실제 PostgreSQL을 거칩니다. 모형 비행기를 풍동에서 시험한 뒤 실제 활주로에서 이륙시켜 보는 단계입니다.

### 시험 순서와 결과
| 단계 | 행동 | 기대 | 결과 |
|---|---|---|---|
| 1 | `/login`에서 시험 계정(quickstart.md의 e2e-t039)으로 로그인 | 대시보드 이동 | 통과 (`POST /auth/login` 200) |
| 2 | 빈 대시보드 확인 | "아직 프로젝트가 없습니다" 안내 | 통과 |
| 3 | "새 프로젝트" → 제목 "PW 테스트 프로젝트", 설명 입력 → "만들기" | 생성 후 상세 화면 이동 | 통과 (`POST /projects` 201) |
| 4 | 메뉴의 "대시보드" 클릭 | 새 카드가 목록에 보임 | 통과 (`GET /projects` 200) |

카드에는 제목 링크, 설명, "완료 0/0 태스크", "마지막 활동: 2026년 11월 10일"이 표시되었습니다.

## 기술 결정
- Playwright는 사용자의 Chrome과 별개인 새 브라우저라 로그인 쿠키가 없습니다. 그래서 첫 화면에서 `auth/me` 401 두 번과 `auth/refresh` 401 한 번이 콘솔 오류로 찍혔습니다. **로그인 전 세션 확인의 정상 응답**이며 버그가 아닙니다.
- 화면 확인은 접근성 스냅샷(역할·이름 기준)으로 하고, 서버 응답은 네트워크 기록으로 확인했습니다.

## 관련 개념
- **E2E(종단 간) 시험**: 화면 → 서버 → DB까지 실제 부품을 모두 연결해 사용자처럼 확인하는 시험입니다.

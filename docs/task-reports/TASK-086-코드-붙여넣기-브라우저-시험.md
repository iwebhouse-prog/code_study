## 작업 요약
코드를 직접 붙여넣어 태스크를 만들고 **언어가 제대로 기록되는지** 실제 브라우저로 확인했습니다. 붙여넣기는 파일 이름이 없어 확장자로 언어를 알 수 없기 때문에, 명세(FR-013)대로 사용자가 언어를 고릅니다. 이름표 없는 상자에 사용자가 직접 "부엌" 스티커를 붙이는 것과 같습니다.

| 단계 | 행동 | 기대 | 결과 |
|---|---|---|---|
| 1 | 붙여넣기 탭 → 파이썬 합계 함수 8줄 입력, **언어는 고르지 않고** 제출 | 막히고 "프로그래밍 언어를 선택하세요." (명세 Edge Case) | 통과 — 선택칸 옆 안내, 요청 안 보냄 |
| 2 | 언어 "Python" 선택 → 제출 | 201, 완료 창 | 통과 — "Task 3. 붙여넣기 합계 함수", 파일 `pasted.py` |
| 3 | 프로젝트 화면 | 카드 "Task 3", 언어 "Python" | 통과 |
| 4 | DB 확인 | upload_method `paste`, 언어 python, 8줄 | 통과 |

언어 선택지는 계약서대로 10개(Python, JavaScript, TypeScript, HTML, CSS, Java, C, C++, Markdown, 일반 텍스트)였습니다.

## 기술 결정
- **"언어 감지 확인"의 의미**: 붙여넣기에서는 자동 감지를 하지 않고 사용자가 고른 언어를 그대로 저장합니다(계약서). 그래서 이 시험은 "고른 언어가 저장·표시되는가"를 확인했습니다. 자동 감지는 T084(확장자)와 T085(여러 파일의 대표 언어)에서 확인되었습니다.
- 붙여넣은 코드는 고른 언어의 확장자로 `pasted.py`라는 이름이 붙어 저장됩니다.

## 관련 개념
- **자동 감지 vs 사용자 선택**: 짧은 코드는 자동 감지가 자주 틀리므로(T065 실험), 붙여넣기는 사용자 선택을 믿습니다.

## 주의할 점 (비고)
- 사용자가 언어를 잘못 고르면(예: JS 코드에 Python) 그대로 저장됩니다. 경고가 필요하면 나중에 내용 감지 결과와 비교하는 기능을 추가할 수 있습니다.

## 작업 요약
비밀번호를 **DB에 그대로 저장하지 않고, 되돌릴 수 없는 형태(해시)로 바꿔 저장하고 확인하는 도구**를 만들었습니다 (`backend/src/utils/security.py`).

비유하면 비밀번호를 믹서기에 간 주스로 만드는 것입니다. 주스를 보고 원래 과일(비밀번호)을 알아낼 수는 없지만, 로그인할 때 같은 과일을 다시 갈아 보면 같은 주스인지 확인할 수 있습니다. 매번 다른 "양념(salt)"을 넣기 때문에 같은 비밀번호라도 사람마다 해시가 다르게 나옵니다.

| 함수 | 하는 일 |
|---|---|
| `hash_password(password)` | bcrypt(비용 12)로 해시 생성 → `users.password_hash`에 저장할 값 |
| `verify_password(password, password_hash)` | 입력한 비밀번호가 저장된 해시와 맞는지 `True`/`False` |

예시 결과: `$2b$12$HsZrIT7jDx.D0YNGoCm7Ge...` (60자, `$2b$` = bcrypt, `12` = 비용)
속도: 해시 1회 약 **0.2초**, 확인 1회 약 0.2초 — 일부러 느리게 만들어 무작위 대입 공격을 어렵게 합니다.

## 기술 결정
- **passlib 없이 `bcrypt` 직접 사용**: passlib은 유지보수가 멈췄고 bcrypt 4.1 이상과 경고·오류가 납니다. 이미 설치된 `bcrypt==5.0.0`만으로 충분합니다.
- **72바이트 초과 비밀번호는 거부(`PasswordTooLongError`)**: bcrypt는 72바이트까지만 읽습니다. 몰래 잘라 쓰면 "앞 72바이트만 같으면 로그인되는" 문제가 생기므로 명확히 거부합니다. 글자 수가 아니라 **바이트** 기준이라 한글은 24자까지입니다. `ValueError`의 한 종류라 API에서 400 오류로 바꾸기 쉽습니다.
- **로그인 때 너무 긴 비밀번호는 오류 대신 `False`**: 그런 비밀번호는 애초에 저장될 수 없으니 "비밀번호가 틀림"으로 답하는 것이 맞고, 서버 500 오류를 막습니다.
- **망가진 해시는 `False`가 아니라 오류**: DB 값이 깨진 것은 데이터 문제라 "비밀번호 틀림"으로 숨기지 않고 드러냅니다.
- **비용 12는 고정, 다른 비용의 기존 해시도 확인 가능**: 개발용 시드 데이터 등 다른 비용으로 만든 해시도 정상 확인됩니다(테스트로 확인).

## 비고
- **비밀번호 규칙(8자 이상, 복잡도)**은 회원가입 입력 검사(T025/T028)에서 처리합니다. 이 도구는 "빈 값"과 "72바이트 초과"만 막습니다.
- **없는 이메일로 로그인할 때의 시간 차이 방지**(가짜 해시로도 `verify_password`를 돌려 응답 시간을 맞추기)는 T025 UserService에서 적용해야 합니다. 그렇지 않으면 응답 속도로 가입 여부가 드러납니다.
- 리프레시 토큰의 해시는 bcrypt가 아니라 SHA-256(data-model.md)이며 T026에서 다룹니다.

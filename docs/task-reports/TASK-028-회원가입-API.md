# TASK-028. 회원가입 API (POST /auth/register)

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
새 손님이 이메일과 비밀번호를 적어 보내면 회원 명부에 이름을 올려 주는 **접수 창구**를 열었습니다. 창구는 이름을 올린 뒤 곧바로 **입장권 두 장**(짧은 것과 긴 것)을 쿠키에 담아 건네므로, 가입한 사람은 다시 로그인하지 않고 바로 대시보드로 갈 수 있습니다.

- 성공하면 201과 함께 회원 정보(id, email, skill_level, created_at, last_login_at)를 돌려줍니다. 비밀번호나 그 암호문은 절대 담지 않습니다.
- 비밀번호가 약하거나 이메일 형식이 틀리면 400, 어느 칸이 문제인지 알려 줍니다.
- 이미 있는 이메일이면 409를 돌려줍니다.

쉽게 말해 헬스장 접수 데스크를 떠올리면 됩니다. 신청서를 받고, 회원증을 만들고, 그 자리에서 출입증까지 목에 걸어 주는 곳입니다. 신청서에 빠진 칸이 있으면 "이메일 칸을 다시 확인하세요"처럼 칸 이름을 짚어 돌려보냅니다. 입력한 비밀번호 내용은 오류 안내에 다시 적지 않으므로 화면이나 기록에 남을 걱정이 없습니다. 오류 문구는 모두 한국어이고, 무엇이 문제인지와 다음에 할 일을 함께 알려 줍니다.

## 왜 이렇게 만들었나
- **창구 직원은 따로 있습니다.** 주소 처리 코드는 받은 내용을 `UserService`와 `TokenService`에 넘기기만 합니다. 프로젝트 규칙(주소 → 서비스 → 모델)을 지키려는 것입니다. 식당 홀 직원이 주문만 받고 요리는 주방에 맡기는 것과 같습니다.
- **가입과 동시에 로그인합니다.** 프론트엔드와 맞춘 계약서(auth-api.md)에 그렇게 적혀 있습니다.
- **쿠키 도장은 한 곳에서만 찍습니다.** 쿠키 옵션을 정하는 함수를 하나만 두어, 나중에 T201에서 보안 옵션을 바꿀 때 한 군데만 고치면 됩니다.

## 기술 결정
- 이메일은 서비스가 소문자로 정리해 저장합니다. 창구는 그대로 넘깁니다.
- 오류 본문은 기존 공통 형식을 그대로 씁니다.

## 관련 개념
- **쿠키**: 브라우저가 대신 들고 다니는 쪽지입니다. HttpOnly를 붙이면 화면 스크립트는 읽지 못합니다.
- **409 충돌**: "이미 있어서 만들 수 없다"는 뜻입니다.

## 주의할 점 (비고)
- 같은 이메일로 동시에 가입해도 DB의 유일 제약이 한 명만 통과시킵니다.
- 가입 시도 횟수 제한은 아직 없습니다(후속 작업).
- 앱 설정을 `app.state`에 보관하도록 `main.py`를 한 줄 고쳤습니다. 쿠키의 Secure 옵션이 "지금 운영 환경인가"에 따라 달라져야 하기 때문입니다. 기존 앱 시험은 모두 그대로 통과합니다.
- 프론트엔드는 주소 `http://localhost:8000/api/v1/auth/register`로 `withCredentials` 요청을 보내야 쿠키를 받을 수 있습니다. `127.0.0.1`을 쓰면 쿠키가 다른 주소 것으로 취급되어 저장되지 않습니다.

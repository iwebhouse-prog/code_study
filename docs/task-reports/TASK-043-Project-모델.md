# TASK-043. Project 모델

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
학습자가 만드는 **프로젝트**를 DB에서 다루는 모델을 만들었습니다. 프로젝트는 여러 학습 태스크를 담는 공책 같은 것입니다. "파이썬 기초"라는 공책 안에 1번, 2번 태스크가 차례로 쌓이는 식입니다.

| 필드 | 내용 |
|---|---|
| `user_id` | 공책 주인. 회원이 탈퇴하면 공책도 함께 지워짐 |
| `title` | 제목(1자 이상, 255자까지) |
| `description` | 설명(선택) |
| `last_activity_at` | 마지막으로 공부한 시각(대시보드 정렬용) |
| `deletion_status`, `trashed_at`, `scheduled_deletion_at` | 휴지통 정보 |

**휴지통 기능도 함께 넣었습니다.** `move_to_trash()`를 부르면 상태가 "휴지통"이 되고, 버린 시각과 30일 뒤 영구 삭제 예정일이 한꺼번에 적힙니다. `restore()`를 부르면 셋이 한꺼번에 원래대로 돌아갑니다. 세 칸을 따로 고치다가 하나만 바뀌는 실수를 막기 위해서입니다. 이 기능은 공통 틀(`SoftDeleteMixin`)에 넣어서 태스크(T061)도 그대로 씁니다.

회원 쪽에서도 `user.projects`로 내 공책 목록을 볼 수 있게 연결했습니다.

## 왜 이렇게 만들었나
- **DB 규칙을 모델에도 적었습니다.** 제목은 비울 수 없고, 휴지통 상태는 "사용 중"과 "휴지통" 두 가지뿐입니다. DB와 같은 이름의 규칙이라 오류 메시지에서 바로 원인을 알 수 있습니다.
- **목록은 필요할 때만 불러옵니다.** 회원을 불러올 때 공책 목록까지 저절로 따라오지 않게 했습니다. 읽어야 할 때만 명시적으로 불러옵니다(지연 불러오기를 막는 비동기 규칙).
- **보관 기간 30일은 한곳에만 적었습니다.** 명세(FR-009F/H)의 30일을 `TRASH_RETENTION` 하나로 관리합니다.

# TASK-064. 파일 검증 도구

## 상태
완료

## 날짜

## 작업 요약
코드를 저장하기 전에 **올라온 파일이 규칙에 맞는지 검사하는 도구**(`file_validator.py`)를 만들었습니다. 공항 보안 검색대처럼, 저장(T067)과 분석(T065·T066)으로 들어가기 전에 한 번 걸러 냅니다. 실패하면 공통 오류 형식(CHK084)과 한국어 안내가 나갑니다.

| 검사 | 규칙 | 오류 코드 | 상태 |
|---|---|---|---|
| 파일 수 | 1~20개 (FR-018) | `no_files`, `too_many_files` | 400 |
| 전체 크기 | 10MB 이하 (FR-014) | `file_too_large` | 413 |
| 확장자 | 12가지, 대소문자 무관, 없는 파일 거절 (FR-015) | `unsupported_file_type` | 400 |
| 바이너리 | 알려진 바이너리 서명 또는 NUL 바이트 (FR-016) | `binary_file` | 400 |
| 제외 폴더 | `.git`, `node_modules`, `.DS_Store`, `__pycache__` (FR-017) | (오류 아님, 걸러냄) | — |

`validate_upload()`는 위 검사를 싼 것부터(개수 → 크기 → 파일별) 차례로 돌리고, 실패하면 **처음 걸린 파일 이름**을 `details`에 담습니다.

## 기술 결정
- **확장자 목록과 10MB는 모델 상수**(`CodeFile.SUPPORTED_EXTENSIONS`, `UploadedCode.MAX_UPLOAD_BYTES`)를 그대로 씁니다. DB 규칙과 검사 규칙이 어긋날 수 없습니다.
- **T063에서 찾은 빈틈 두 가지를 막았습니다.** `.PY` → `.py`로 바꾸고, 확장자 없는 파일(`Makefile`)은 거절합니다.
- **바이너리 판별은 "UTF-8로 읽히는가"가 아니라 NUL 바이트와 서명으로 합니다.** 그래야 옛 윈도 편집기로 저장한 CP949 한글 코드도 텍스트로 인정됩니다. 앞부분 8KB만 보므로 큰 파일도 빠릅니다.
- 크기 초과 오류 본문은 CHK084의 예시와 글자 그대로 같습니다.

## 관련 개념

## 주의할 점 (비고)
- **명세와 다른 점**: FR-015는 9가지 형식을 적었지만, 마이그레이션과 research.md는 `.ts .jsx .tsx`를 더해 12가지입니다. DB 기준(12가지)을 따랐습니다. spec.md를 고칠지는 결정이 필요합니다.
- 명세는 파일이 너무 많을 때 "폴더 업로드를 사용하세요"라고 안내하지만, 폴더 업로드도 20개 제한이 같아 "여러 태스크로 나누어"로 바꿨습니다.
- UTF-16 파일은 NUL 바이트가 있어 바이너리로 거절됩니다. 코드 파일로는 드물어 그대로 두었습니다.
- 폴더 경로의 `../` 같은 위험한 경로 검사는 넣지 않았습니다. 저장 이름은 UUID라 위험하지 않지만, 경로를 화면에 보여 줄 T067·T069에서 다시 확인해야 합니다.

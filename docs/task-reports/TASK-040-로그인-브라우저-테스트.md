# TASK-040. 로그인 브라우저 테스트

## 상태
완료

## 날짜
2026-11-09

## 작업 요약
실제 브라우저에서 가입해 둔 계정으로 로그인하고, 로그인한 사람만 들어갈 수 있는 대시보드에 들어가지는지 확인했습니다. 회원증을 찍고 회원 전용 열람실 문이 열리는지 직접 확인한 셈입니다.

진행 순서와 결과는 다음과 같습니다.

1. 먼저 로그아웃해 비로그인 상태를 만들었습니다(서버 응답 204).
2. 로그인 화면(`/login`)을 열었습니다. 이 순간 화면은 "지금 누구인지" 서버에 물었고(`/auth/me`), 서버는 401로 "로그인 안 됨"이라고 답했습니다. 그래서 로그인 화면이 그대로 보였습니다.
3. `e2e-t039@example.com`으로 로그인했습니다. 서버가 **200(성공)** 으로 답했습니다.
4. **대시보드("내 프로젝트", `/`)로 이동**했습니다.
5. 앞선 확인에서는 로그인 상태로 새로고침해도 로그인이 유지되었습니다. 서버에 다시 물었을 때 200으로 답했습니다.
6. 보호된 페이지(`/trash`)에서 로그인 화면으로 밀려난 뒤 로그인하면, 대시보드가 아니라 원래 가려던 `/trash`로 돌아가는 것도 확인했습니다.

## 왜 이렇게 시험했나
- 로그인 성공의 진짜 증거는 "회원 전용 화면에 실제로 들어가지는가"입니다. 그래서 응답 번호와 이동한 화면을 함께 확인했습니다.
- 원래 가려던 화면으로 돌려보내는 기능은 사용자가 가장 자주 느끼는 편의라서 함께 보았습니다.

## 관련 개념
- **세션 확인**: 페이지를 열 때마다 쿠키를 들고 "나 누구야?"라고 서버에 물어 로그인 상태를 정하는 방식입니다.
- **돌아갈 주소 기억하기**: 로그인 화면으로 보낼 때 원래 가려던 주소를 함께 넘겨, 로그인이 끝나면 그곳으로 되돌려 보내는 방식입니다. 사용자가 같은 길을 두 번 찾지 않아도 됩니다.

## 주의할 점 (비고)
- 브라우저 도구의 네트워크 기록에 로그아웃 요청 한 건이 503으로 표시된 적이 있습니다. 같은 요청을 화면 코드는 204로 받았고, 서버 기록에도 로그아웃 3건이 모두 204로만 남아 있어 기록 도구의 오표시로 판단했습니다.
- 개발 모드에서는 화면을 두 번 그리는 점검 기능 때문에 `/auth/me`가 한 번에 두 번 호출됩니다.

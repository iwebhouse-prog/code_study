## 상태
완료 (통과)

## 날짜
2026-11-16

## 작업 요약
코드처럼 보이는 이름이지만 **내용은 그림 파일인 것을 서버가 알아보고 거절하는지(FR-016)** 실제 브라우저로 확인했습니다. 상자에 "책"이라고 적혀 있어도 열어 보고 돌멩이면 돌려보내는 것과 같습니다.

시험 파일 `fake.py`(16바이트): 이름은 `.py`지만 내용은 PNG 그림 파일의 시작 부분(`\x89PNG…`)입니다.

| 단계 | 기대 | 결과 |
|---|---|---|
| 파일 업로드 탭 → `fake.py` 선택 | 확장자는 허용 목록이라 화면에서는 통과 | 통과 — 선택 목록에 표시 |
| 태스크 만들기 | 서버가 내용을 보고 400 `binary_file` | 통과 |
| 화면 표시 | 서버의 `message`와 `suggestion`을 창 위쪽 경고(alert)로 | 통과 — "소스 코드 텍스트 파일만 업로드할 수 있습니다." / ".py, .js, .html 같은 텍스트 형식의 코드 파일을 업로드하세요." |
| 창 상태 | 닫히지 않고 입력 유지(고쳐서 다시 시도 가능) | 통과 — 제목·파일 선택 유지 |
| DB·디스크 | 아무것도 남지 않음 | 통과 |

T087의 직접 전송 시험에서도 같은 파일을 API로 보내 400 `binary_file`, `details.file_name: "fake.py"`를 확인했습니다.

## 기술 결정
- 바이너리 판별은 브라우저가 아니라 **서버만** 합니다(T064의 파일 서명·NUL 바이트 검사). 그래서 이 시험이 "서버 오류를 화면에 제대로 보여 주는가"까지 함께 검증합니다.
- 경고는 `role="alert"`로 표시되어 화면 읽기 프로그램도 바로 읽어 줍니다.

## 관련 개념
- **파일 서명(매직 넘버)**: 파일 맨 앞 몇 바이트로 실제 형식을 알아보는 방법. 이름(확장자)은 쉽게 바꿀 수 있지만 내용은 속이기 어렵습니다.

## 주의할 점 (비고)
- 이 오류의 콘솔 기록(400)은 의도한 거절입니다.
- 오류 문구에 어떤 파일이 문제인지(`fake.py`)는 화면에 나오지 않습니다. 여러 파일을 올릴 때를 위해 `details.file_name`을 보여 주는 것을 고려할 수 있습니다.

## 상태

## 날짜

## 작업 요약
학습 공책(프로젝트)을 다루는 **창구 직원**을 만들었습니다. 창구 직원은 다섯 가지 일을 합니다.

| 업무 | 하는 일 |
|---|---|
| 만들기 `create` | 제목·설명을 받아 새 공책을 만듭니다. 제목 앞뒤 빈칸은 지우고, 설명이 빈칸뿐이면 "설명 없음"으로 둡니다. |
| 목록 `list_active` | 내 공책 중 휴지통에 없는 것을 최근에 공부한 순서로 보여 줍니다. |
| 꺼내 보기 `get` | 공책 하나를 찾아 줍니다. |
| 고치기 `update` | 제목이나 설명 중 바꾸라는 것만 바꿉니다. "설명 지우기"와 "설명은 그대로"를 구분합니다. |
| 휴지통에 넣기 `move_to_trash` | 공책을 휴지통에 넣습니다. 30일 뒤 영구 삭제 예정일도 함께 적힙니다(T043). |

잘못된 요청에는 명세(CHK084)에 정해진 문장으로 답합니다.

- 제목이 비었을 때: "프로젝트 제목은 최소 1자 이상이어야 합니다." (400)
- 공책이 없거나 휴지통에 있을 때: "요청한 프로젝트를 찾을 수 없습니다. 삭제되었거나 존재하지 않는 프로젝트입니다." (404)

## 왜 이렇게 만들었나
- **휴지통에 있는 공책은 "없음"으로 취급합니다.** 휴지통 밖의 화면에서 버린 공책을 고치거나 다시 버리는 일을 막습니다. 휴지통 화면용 기능은 T170 이후에 따로 만듭니다.
- **"안 바꿈"과 "지우기"를 구분합니다.** 설명 칸을 보내지 않은 것과 빈칸으로 보낸 것은 다른 뜻이라, 특별한 표시(`UNSET`)로 구분했습니다.
- **잘못된 제목은 아무것도 바꾸기 전에 거절합니다.** 제목 검사가 먼저 실패하므로 반쯤 고쳐진 채 남지 않습니다(테스트로 확인).
- **소유자 확인은 다음 작업(T045)입니다.** 아직 이 서비스를 쓰는 API 주소가 없어 바깥에 드러나지 않습니다.
